# 劇情小劇場

任務開頭「先看看發生什麼事」上方的小畫面：店員和你站在咖啡店櫃檯前，誰說話誰就動，部分台詞會有道具動作。

狀態：**未做**（規格已定，等待實作）。

## 目的與原則

- **輔助理解，不取代文字**：聊天泡泡、中文、「慢速」按鈕都維持原樣，學習內容還是靠文字和聲音。小劇場只是讓人一眼看出「誰在跟誰說話、在做什麼」。
- **純裝飾**：不能按、不能聚焦，所以不違反「能按的東西都是有框的按鈕」。
- **安靜**：和街景一樣大部分時間靜止，只有說話和道具動作時才動。
- 系統設定「減少動態」時完全靜止（見下方）。

## 畫面內容

| 項目 | 規格                                                                                      |
| ---- | ----------------------------------------------------------------------------------------- |
| 舞台 | 128×64 邏輯像素，用 `Painter` 介面繪製，只用街景調色盤（`src/game/palette.ts`），硬邊像素 |
| 背景 | 咖啡店內：櫃檯（佔下方約三分之一）、咖啡機、菜單板、吊燈的暖光                            |
| 你   | 站在左邊、面向右，沿用主角 `walker` 的站姿（`idleKey('walker')`，16×24）                  |
| 店員 | 在櫃檯後面、面向左，新畫一張 16×24 的圖，只露出上半身，下半身被櫃檯擋住                   |

角色依台詞的 `role` 決定：`barista` 是店員，`guide` 是你。

第一版只做咖啡廳。搬家第一天單元的房東（`landlord`）還沒有角色圖和背景，所以那個單元先只顯示聊天泡泡。

## 動作

### 說話

- 說話的人以 `steps()` 上下跳 1 像素，從聲音開始播放到 `playAudio()` 結束為止（`playAudio` 會在音檔播完時 resolve）。
- 點泡泡重聽或按「慢速」時也會動，動的是那一句的說話者。
- 換下一句時，上一句的跳動立刻停止。

### 道具動作

台詞可以加一個選填欄位 `stage`，有三種動作：

| `act`  | 需要 `item` | 畫面                                                                             |
| ------ | ----------- | -------------------------------------------------------------------------------- |
| `want` | 要          | 說話者頭上冒出想法泡泡，裡面是該單字的像素圖（24×24，1 倍）；下一句出現時消失    |
| `ask`  | 不可以有    | 說話者頭上出現「?」泡泡；下一句出現時消失                                        |
| `give` | 要          | 單字圖卡從說話者那邊沿著櫃檯滑到對方那邊，之後留在櫃檯上，直到這個任務的劇情結束 |

- 單字圖沿用 `ItemIcon`；沒有像素圖的單字顯示 emoji 備用圖。
- 每個任務的舞台都從空的狀態開始，不會帶到下一個任務。

## 版面

- **直向（手機）**：舞台在聊天紀錄上方、置中。整數倍率 1 或 2：面板內寬 ≥ 256 邏輯像素時用 2 倍，否則 1 倍。聊天紀錄的最大高度相應縮短。
- **橫向（電腦）**：舞台在左、聊天紀錄在右，放在現有的劇情卡片裡（最寬 440 邏輯像素）。

## 減少動態

- 角色完全靜止，說話時不跳動。
- 泡泡直接出現，沒有彈出動畫。
- `give` 不滑動，圖卡直接出現在終點。

## 無障礙

- 舞台整塊加上 `aria-hidden="true"`，不能聚焦。
- 所有資訊本來就在泡泡裡，螢幕閱讀器和鍵盤操作完全不變。

## 內容格式

`scene[]` 的每句台詞可以加 `stage`：

```json
{
  "id": "t1_2",
  "role": "guide",
  "speaker": "player",
  "en": "Can I get a latte, please?",
  "zh": "可以給我一杯拿鐵嗎？",
  "chunkId": "can_i_get",
  "stage": { "act": "want", "item": "latte" }
}
```

內容檢查（`src/content/validate.ts`）：

- `act` 只能是 `want`、`ask`、`give`。
- `want` 和 `give` 一定要有 `item`，而且必須是同一個單元裡的單字 id。
- `ask` 不能有 `item`。

咖啡廳單元的提示：

| 台詞 | 內容                           | `stage`         |
| ---- | ------------------------------ | --------------- |
| t1_2 | Can I get a latte, please?     | `want` latte    |
| t3_1 | How much is it?                | `ask`           |
| t3_3 | Sorry, can you say that again? | `ask`           |
| t3_4 | Six fifty. Here you go.        | `give` sandwich |

其他台詞只有說話動作。任務 2 沒有適合的道具（缺外帶杯的圖），先不加。

## 程式位置（預定）

| 檔案                          | 內容                                                                                 |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| `src/ui/stage/stageState.ts`  | 純函式 `stageAt(lines, shown)`：算出第 N 句時的泡泡、櫃檯上的道具、正在滑動的 `give` |
| `src/art/stage/cafe.ts`       | 咖啡店背景的繪製函式、店員圖、舞台尺寸                                               |
| `src/art/stage/index.ts`      | 每個單元的舞台設定：背景，以及 `role` 對應到哪個角色、站哪一邊                       |
| `src/ui/stage/SceneStage.tsx` | 背景畫一次後快取成圖片；角色用 `spriteRuns()` 轉成內嵌 SVG；道具用 `ItemIcon`        |
| `src/ui/stage/stage.css`      | 動畫一律用 `steps()`，只動 `transform` 和 `opacity`                                  |

## 新增地點時要做的事

1. 畫 128×64 的背景（同一個調色盤）。
2. 新角色需要的話，畫 16×24 的角色圖。
3. 在 `src/art/stage/index.ts` 加上這個單元的舞台設定。
4. 在台詞上加 `stage` 提示（選填）。

沒有舞台設定的單元不會顯示舞台，畫面維持只有聊天泡泡。

## 測試

- `tests/stageState.test.ts`：每一句的泡泡、`give` 之後道具留在櫃檯、每個任務重新開始。
- `tests/stageArt.test.ts`：只用調色盤的顏色、沒有小數座標、不超出 128×64、同樣輸入畫出同樣的畫面；店員圖通過 `validateSprite`。
- `tests/content.test.ts`：合法的提示通過；錯的 `act`、缺 `item`、`item` 不存在、`ask` 帶 `item` 都要報錯。
- 實際操作：直向和橫向各截圖一次，並用「減少動態」模擬確認畫面完全靜止。
