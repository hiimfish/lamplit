## 需要使用者處理的事

1. **在真的手機上玩一次**：目前只用電腦瀏覽器模擬過手機。
2. **測試錄音和發音評分**：開發用的瀏覽器沒有麥克風，錄音和裝置上的發音評分（2026-11-25 取代語音辨識）都沒在真實裝置上試過，手機上評分要多久也還不知道。注意：手機透過區網 http 連線時瀏覽器不允許錄音，要用 HTTPS：開發時執行 `npm run dev:https`（步驟見 [architecture.md](architecture.md) 的「手機上測錄音」），或部署到 GitHub Pages 後測試。手機上要試的項目（用 https 開）：
   - 第一次開跟著說或按「評分」時，下載發音模型的說明（約 95MB）和進度是否清楚；下載完再開不會再下載。
   - 手機上一句評分要等多久（「評分中…」），跟我說和跟著說都要試；較舊的手機會不會太慢。
   - 要求麥克風權限的時機是否清楚；跟著說開著時只問一次。
   - 每句播完後會自己開始錄，還是要按「說」（iOS 可能要按，鍵 R）；說完後約 0.8 秒會不會自己停。
   - 每句播完到下一句的音量和節奏是否合適。
   - 唸清楚和唸不清楚的字，分數和句子上的線（未滿 40 分的字是虛線、40–69 分的字是細線）是否看得懂，分數和自己的感覺是否差不多。
   - 連續 3 句沒有聲音，跟著說是否自動關掉。
   - 拒絕麥克風權限或模型下載失敗後，是否退回「每句停一下」並顯示一行說明。
   - 螢幕鎖定時麥克風是否停止。
   - 麥克風開著時，咖啡館音樂是否靜音。
   - 完成畫面的「跟著說 N 句，平均 S 分」是否顯示。
