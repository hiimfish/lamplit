## 需要使用者處理的事

1. **在真的手機上玩一次**：目前只用電腦瀏覽器模擬過手機。
2. **測試錄音和語音辨識**：開發用的瀏覽器沒有麥克風，這兩項沒在真實裝置上試過。注意：手機透過區網 http 連線時瀏覽器不允許錄音，要用 HTTPS（例如部署到 GitHub Pages 後測試）。
3. **確認 Google 的服務條款**：生成的音檔能不能放進公開的網站和 repo，官方頁面沒寫清楚，上線前一定要確認。
4. **決定 repo 要不要公開**：GitHub Pages 免費方案需要公開。
5. **試聽新內容**：之後每個新地點的發音都需要人耳確認。
6. **英文內容審閱**：句子最好請英文好的人看過。

## 已知問題

- 低優先的程式問題：見 [vocab-quiz.md](vocab-quiz.md) 的「待改進」。
- 「水」的像素圖最不容易辨認；三明治和蛋糕的白色部分和背景有點糊在一起。

- 錄音和辨識時「按鈕是否正確停用」沒有自動化測試（專案沒有模擬瀏覽器的測試環境）。

## 風險

| 風險                                 | 程度 | 對策                                                            |
| ------------------------------------ | ---- | --------------------------------------------------------------- |
| 內容量大，句子要自然道地             | 高   | 內容檢查自動化；上線前請人審閱                                  |
| 成人覺得太幼稚或太像考試             | 高   | 生活模擬包裝、真實情境；每個階段都試玩                          |
| 每個新單字都要畫像素圖               | 中   | 圖鑑式的固定規格（24×24、同一調色盤），有測試檢查每個單字都有圖 |
| 生成音檔的使用條款                   | 中   | 上線前確認                                                      |
| 語音辨識只有部分瀏覽器支援、不一定準 | 中   | 只當額外參考，不影響評分；主要靠錄音比對                        |
| 換裝置進度不會同步                   | 低   | 之後做存檔匯出／匯入；帳號同步不在範圍內                        |
