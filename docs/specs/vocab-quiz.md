# 單字測驗（vocab quiz）

題型、出題、批改與回饋的規格。實作在 `src/learning/`（出題、批改）和 `src/ui/minigames/`（畫面）。

## 題型

| 題型           | 內容                                                                                  | 狀態                           |
| -------------- | ------------------------------------------------------------------------------------- | ------------------------------ |
| 聽音選圖／選字 | 自動播放一個單字或詞塊，從選項中選出聽到的那個；單字選項附像素小圖                    | 已做                           |
| 選回應         | NPC（店員、房東）說一句話，選出最自然的回應                                           | 已做                           |
| 排句子         | 把打亂的字塊排成句子                                                                  | 已做                           |
| 跟我說         | 聽示範、自己念、錄音後和示範輪流比對；可選擇用語音辨識                                | 已做                           |
| 聽辨挑戰       | 聽一個字，從只差一個音的兩個字（fan/van、ship/sheep）選出聽到的；答完可兩個都聽來比較 | 已做（單一聲線；多種聲線未做） |
| 聽力填空       | 聽一段對話，填入缺少的字                                                              | 未做                           |
| 打字拼字       | 聽發音後打出單字（手機改用字母方塊）                                                  | 未做                           |
| 角色扮演大挑戰 | 自己完成整段對話：輪到你時，把字塊排成你要說的話                                      | 已做（每個地點的第 8 個任務）  |

## 出題

任務練習（`buildTaskPractice`）依這個順序，由易到難：

1. 每個新單字一題「聽音選圖」。
2. 每組新對比詞兩題「聽辨挑戰」，兩個字各考一次，先後隨機。選項只有這兩個字，不附圖。
3. 每個新詞塊一題「聽音選字」。
4. 劇情中每句「你」的台詞，若前一句是 NPC 說的，出一題「選回應」。提示文字依那句 NPC 台詞的角色寫「店員說了這句」或「房東說了這句」。
5. 每個新詞塊一題「排句子」（只有一個字的詞塊略過）。
6. 每個新詞塊一題「跟我說」。

搬家第一天每個任務有 2 個單字、2 組對比詞、2 個詞塊，所以一個任務 14 題，比咖啡廳（7～11 題）長。

規則：

- 選項一定打亂，至少 2 個，正確答案只出現一次。
- 干擾選項來自同單元的其他單字或詞塊，以及詞塊自己的 `distractors`（每個都標了錯誤類型）。
- 排句子的字塊一定不會剛好是正確順序。
- 排句子的字塊去掉頭尾標點（「latte,」變成「latte」），避免標點提示位置；字中間的撇號和連字號保留（I'm、take-out）。
- 出題用固定種子的亂數，方便測試重現。
- 角色扮演大挑戰（`buildRolePlayTurns`）：照對話順序，每句「你」的台詞出一題排句子。
  - 字塊來自整句台詞，可以比詞塊多字（例如 Can I get a muffin, please?）。
  - 可接受的答案是台詞本身；台詞和詞塊完全一樣時，再加上詞塊的 `accept`。
  - 用那句的詞塊排複習。
  - 提示寫「換你說：把單字排成你要說的話」。中文不會因為設定的「顯示中文」自動出現，要按「看中文」，算用了幫助，因為這一關的提示是前面的對話。
- 今日複習（`buildReviewQuestions`）以「聽音選圖／選字」和「排句子」為主；到期的對比詞出一題「聽辨挑戰」，隨機考其中一個字。

## 批改

- 比對前先正規化：去掉重音符號（café 當成 cafe，先用 NFD 拆開再過濾）、不分大小寫、去掉標點、把彎引號換成直引號、合併空白。
- 只和「可接受答案」清單比對（詞塊的 `en` 加上 `accept`），不評分自由作答的英文。
- 答錯時判斷錯誤類型：冠詞、單複數、拼錯、順序、少字、多字、其他。每種都有中文提示（`src/learning/errorHints.ts`）。
- 「選回應」答錯時，用該選項標註的錯誤類型給提示。
- 排句子時字都對、只有順序錯，一定判成「順序」，不會因為某個比較短的可接受說法字母比較接近，就判成「多字」。

## 回饋

- 答對顯示「答對了！」，答錯顯示「不太對喔」，並附上提示和正確說法。不只靠顏色表示對錯，也有 ○ / × 標記。
- 作答後一定播放正確的發音。
- 離開題目或介紹卡時（按「繼續」、「開始練習」或「先回小鎮」）停止正在播放的發音。
- 按「繼續」才進下一題，讓回饋停留在畫面上。答題後焦點會自動移到「繼續」，回饋文字會被螢幕閱讀器讀出。
- 按「慢速」會被記為「用了幫助」，影響複習評分（見 [learning.md](learning.md)）。

## 跟我說

- 永遠不會被判錯。
- 「現在不方便說話」可以跳過，記為用了幫助。
- 錄音只留在當次練習的記憶體裡，不會儲存或上傳。
- 錄音期間和等待麥克風權限期間，會停用會衝突的按鈕；離開題目時一定釋放麥克風。
- 錄音格式：依序試 `audio/webm;codecs=opus`、`audio/webm`、`audio/mp4`、`audio/ogg;codecs=opus`，用第一個瀏覽器能錄的格式（Chrome 是 WebM，舊版 Safari 是 MP4）；都不支援時讓瀏覽器自己選。錄音只在同一個瀏覽器播放，所以不需要統一格式。
- 不能錄音時顯示具體原因，結尾都提示可以先跳過這一題：
  - 用 http 開啟（不是安全連線）：請改用 https 網址。這項最先檢查，因為 http 時瀏覽器會把麥克風功能整個隱藏，不檢查的話會被誤判成「沒有麥克風功能」。
  - 瀏覽器沒有開放麥克風（例如 LINE、FB 的內建瀏覽器）：請改用 Safari 或 Chrome。
  - 瀏覽器沒有錄音功能：iPhone 請更新到 iOS 14.5 以上。
  - 沒有麥克風權限、找不到麥克風、麥克風被其他 App 使用（例如通話中），以及其他錯誤，各有自己的訊息。
- 語音辨識在 http 開啟時也會說明需要 https。

### 語音辨識（選用）

- 只在瀏覽器支援時顯示「辨識」按鈕。
- 第一次按下時先說明：辨識由 Chrome 完成，聲音會傳給 Google 處理。按「繼續辨識」才開始收音，按「取消」就不辨識，下次還會再問。
- 辨識中會停止所有播放並停用示範播放和錄音，避免把示範音誤判成學習者的聲音。
- 8 秒逾時；離開題目時一定取消。
- 辨識結果只給正面的參考（哪些字有聽到），不影響評分。

## 待改進

來源：2026-11-22 程式碼審查中嚴重度「低」的項目。高與中嚴重度的問題已另外修正，不列在這裡。

### 學習與存檔

- **存檔的 `__proto__` 鍵**（`src/core/save.ts`）：卡片或任務的 id 若是 `__proto__`，會改掉該物件的原型，那一筆資料會悄悄消失。改法：略過這個鍵，或用 `Object.create(null)`，或用正規表示式檢查 id。
- **選回應題可能把正確說法判錯**（`src/learning/questionGen.ts`）：檢查重複選項時沒有考慮詞塊的 `accept` 清單。若另一個詞塊剛好等於某個可接受的說法，會被當成錯誤選項。目前的內容不會觸發。
- **`?debugDate` 的日期解析**（`src/core/save.ts` 的 `resolveNow`）：年份 `0001` 會變成 1901，`2026-02-31` 會變成 3 月 3 日。只影響除錯參數。
- **存檔匯出／匯入還沒接上介面**（`src/core/save.ts`）：接上之前要加匯入代碼的長度上限，並拒絕比目前版本新的存檔（現在會默默降級）。
- **沒有計分題時給 3 顆星**（`src/learning/sessionPlan.ts`、`src/ui/ReviewScreen.tsx`）：答對率被當成 100%。目前的內容不會發生。

### 介面與無障礙

- **「播放我的錄音」不受發音音量控制**（`src/ui/minigames/useRecorder.ts`）：用的是獨立的 `Audio` 元素，沒有接到發音音量。
- **辨識被拒絕權限時只顯示通用訊息**（`src/audio/recognize.ts`）。
- **選回應題的回覆音檔 id 是用字串取代組出來的**（`src/ui/minigames/ChooseReply.tsx`）：id 格式改變就會播錯句子。改法：出題時直接帶上回覆的 `audioId`。
- **ARIA 細節**：設定的單選群組沒有方向鍵操作；「顯示中文」開關的名稱重複了狀態；愛心和星星的 `aria-label` 掛在一般 `span` 上，應加 `role="img"`。（「自動捲動沒有尊重減少動態」已確認沒有這個問題：對話紀錄是瞬間捲動，`focusAndReveal` 在減少動態時不用平滑捲動。）
- **`index.html` 的 `theme-color` 和背景色不一致**：`#2b2540` 對上 `--screen-bg` 的 `#1d1a2b`。

### 音訊

- **開始音效不受音效音量控制**（`src/audio/audioContext.ts`）：直接接到輸出，略過音效音軌。
- **音檔讀取失敗會被記住到重新整理為止**（`src/audio/pronounce.ts`）：一次 404 或伺服器錯誤，那個音檔就一直改用瀏覽器語音。
- **`unlockAudio` 的 `resume()` 可能產生未處理的 Promise 錯誤**（`src/audio/audioContext.ts`）。

### 場景

- **「窗戶亮燈」動畫常常選到咖啡廳窗戶**（`src/game/street/plan.ts`）：咖啡廳的窗戶永遠是亮的，所以看不出效果。改法：篩選時排除咖啡廳，並加測試。
- **殘留的材質**：畫面縮小後，多出來的 `street-toggle-N` 材質不會移除。

### 腳本與設定

- **音檔腳本只重試一次**（`scripts/gen-audio.mjs`）：固定等 1.5 秒、忽略 `Retry-After`，網路例外也不會重試。改法：指數退避重試 3 次。
- **小問題**：
  - `package.json` 沒寫 `engines`，但 gen-audio 直接匯入 `.ts`，需要支援 type stripping 的 Node 版本。
  - `check-font-glyphs.mjs` 缺字時仍以 0 結束。
  - `spike-tts.mjs` 的輸出路徑相對於目前目錄，而不是專案根目錄。
  - `tests/genAudio.test.ts` 會留下暫存資料夾。
